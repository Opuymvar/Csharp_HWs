1) Абстрактный класс может содержать обычные поля. Интерфейс не может хранить поля состояния конкретного экземпляра
2) Абстрактный класс может иметь конструктор. Интерфейс не может иметь конструктор т.к не создаёт собственные экземпляры.
3) класс может наследоваться только от одного другого класса. но очень много типов 
4) Абстрактный класс может содержать полностью готовые методы. интерфейсы тоже
5) Абстрактный класс может объявить abstract-свойство,Интерфейс позволяет объявлять свойства которые реализуют наследники.
6) Оба типа могут использоваться для объявления переменных  IDamageable target
7) Абстрактный класс может наследоваться от другого класса. Интерфейс не может наследовать класс но может наследовать другие интерфейсы 
8) Абстрактный класс может содержать приватные методы.  приватные методы также допустимы в интерфейсах.

*) IDamageble -> Character -> (Player ->(IInteractable; IHealable) ; Enemy ; NPC -> (IInteractable))
Абстрактный класс Character используется потому, что у всех трёх сущностей есть общие Name, HP и одинаковая  логика урона. Интерфейс IInteractable определяет дополнительную способность. Интерфейс IHealable определяет способность восстанавливать своё здоровье

абстрактный класс для общего состояния и базовой реализации, а интерфейс для описания способностей, которые  встречаться у разных объектов независимо от их наследования.
